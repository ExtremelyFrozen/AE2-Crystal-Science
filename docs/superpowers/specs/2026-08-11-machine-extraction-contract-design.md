# 机器外部抽取一致性修复设计

## 背景

所有采用 `SideConfigComponent` 和 `AppEngInvComponent` 的机器都会向外部管道暴露物品能力。当前实现允许调用方在模拟抽取时看到输入库存或禁止抽取侧的物品，而正式抽取会返回空栈。这违反了物品能力的模拟与执行一致性约定，可能使管道把模拟结果当作真实物品搬运，导致刷物品。

## 目标

- 外部能力的模拟抽取结果必须与正式抽取结果一致。
- 仅配置为 `EXTRACT` 或 `ALL` 的面可以从输出库存抽取。
- 输入库存不能被外部能力抽取，包括模拟抽取。
- 保持输出库存不可插入、输入库存可插入的既有规则。

## 方案

在两层包装器中消除“模拟时放行、执行时拒绝”的特殊分支：

1. `AppEngInvComponent` 的 `INPUT` 包装器始终拒绝抽取。
2. `SideConfigComponent` 的侧面包装器仅在该侧策略允许抽取时委托抽取；模拟和执行采用同一判断。

这样，管道无论先调用模拟还是直接执行，都只能看到实际可抽取的输出物品。该改动位于全部机器共享的能力路径，不为各机器添加重复逻辑。

## 验收与测试

新增 `GameTest`，使用 `PulseCentrifugeBlockEntity` 代表标准机器能力：

- 输入槽含物品时，默认侧的模拟与正式抽取都必须返回空栈。
- 输出槽含物品且侧面为 `ALL` 时，模拟可见物品，正式抽取会移除相同数量。
- 输出槽含物品但侧面为 `INSERT` 或 `NONE` 时，模拟与正式抽取都必须返回空栈，库存保持不变。

运行 `./gradlew runGameTestServer` 验证新增测试与现有游戏测试。
